# 사용자 여정 — 앱 설치 후 시나리오

> 인터랙티브 프로토타입: https://claude.ai/artifact/FwgVopMrC3KRzqbdDXD37e (비공개, 공유 메뉴에서 팀에 공유)
> 엔진 설계: [engine-design.md](./engine-design.md) · 시나리오 100선: [scenarios.md](./scenarios.md)
> 앱 이름 '파킹메모'는 가칭. 기압·거리·신뢰도 수치는 설계 가설을 보여주는 예시 값.

## 한 줄 요약

사용자가 하는 일은 **처음 권한 3개를 허용하는 것(약 30초)**뿐이다. 이후 주차는 0탭, 귀환은 0탭(iOS는 위젯 1탭), 틀렸을 때만 1탭으로 교정한다.

## 장별 흐름

| 장 | 시점 | 사용자가 보는 것 | 사용자가 하는 일 | 엔진 |
|---|---|---|---|---|
| 1. 설치 | Day 0 | 한 문장 소개 → 권한 3개(이유 한 줄씩) → "쓸수록 정확해져요" 기대치 안내 | 필수 5탭 | 센서 점검, 차·집 자동 학습 대기 |
| 2. 첫 주차 | Day 1 저녁 | 운전 중 화면 없음 → 집 도착 후 "B3에 주차했어요" 알림 1회(새 장소라서) → 잠금화면 위젯 | 0탭 (사진은 선택) | 지하 진입 지점 기록, 10분 되감기로 하차 시점 확정, 차↔집 높이차 48.6 m 저장, 사진 글자 인식으로 층 이름 확정 |
| 3. 첫 귀환 | Day 2 아침 | 엘리베이터에서 "B3로 내려가세요" → 단계 안내("15 m 직진 후 오른쪽") + 넓은 화살표 → "이 근처예요" + 기둥 사진 → 시동 걸면 자동 종료 | Android 0탭 / iOS 위젯 1탭 | 날씨로 기압이 바뀌어도 엘리베이터 변화량만 사용, 차 BT 재연결 순간을 정답으로 학습 |
| 4. 잘못 내린 층 | 다른 날 아침 | B2에서 내리자마자 "▼ 한 층 더 내려가세요" + 진동 | 0탭 | 내린 뒤 평탄부 높이 불일치 감지 |
| 5. 2주 뒤 | 10번째 귀환 | 처음부터 좁은 화살표 + 정확한 거리, 가까울수록 빨라지는 진동, 코앞에서 화면 점멸 | 0탭 | 장소 학습(레벨·엘리베이터·통로 방향) + 개인 보폭 학습으로 T1 도달 |
| 6. 가끔 생기는 일 | — | 분리수거: 아무것도 안 뜸 / 층 오류: 배지 눌러 교정 / 발렛: "차를 맡겼어요" / 기록 실패: 아는 것만 표시 | 많아야 1탭 | 조용한 무장·해제, 교정 즉시 학습, 발렛 자동 분류, T4 강등 |

## 알림 정책

- **처음 2주**: 주차할 때마다 저장 알림을 보낸다. 앱이 일하고 있다는 믿음을 쌓는 기간.
- **이후**: 새 장소이거나 신뢰도가 낮을 때만 알림을 보내고, 평소에는 위젯만 갱신한다.
- 차를 찾는 상황이 아니면 소리·진동을 내지 않는다.

## 한 달 동안 사용자가 하는 일 (아파트 거주, 주 5일 출퇴근 기준 추정)

| 행동 | 횟수 |
|---|---|
| 첫 설정 | 1회 (약 30초) |
| 주차할 때 | 0탭 × 약 20회 |
| 찾으러 갈 때 | Android 0탭 / iOS 위젯 1탭 × 약 20회 |
| 층 교정 | 처음 1~2회, 이후 거의 없음 |
| 기둥 사진 | 새 장소마다 선택 |

## 사업 관점 체크포인트

| 항목 | 내용 |
|---|---|
| 가치를 처음 체감하는 순간 | 첫 귀환 때 엘리베이터 안에서 "B3로 가세요"가 뜨는 순간 (Android에서 가장 강함) |
| 이탈 위험 1 | 권한 거부, 특히 '항상 위치' → 이유 한 줄 설명, 거부해도 위젯 수동 기록으로 사용 가능 |
| 이탈 위험 2 | 첫 귀환이 사진 위주라 실망 → 설정 마지막 화면에서 미리 기대치 안내 |
| 이탈 위험 3 | 기록 실패 1회로 신뢰 붕괴 → 틀린 화살표 대신 "모른다"를 솔직하게 표시 |
| 이탈 위험 4 | 배터리 걱정 → 운전 중과 하차 후 10~15분만 동작, 사용량 공개 |
| 핵심 지표 | 일일 활성 사용자보다 **자동 기록 유지율**과 **찾기 성공률** |
| 유료 전환 지점 | 앱만으로 안 되는 상황(가족이 차 이동 등)이 실제로 생긴 직후 차량 태그 제안, 월 1회 이하 |
