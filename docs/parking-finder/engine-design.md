# 주차 위치 찾기 엔진 — 논리 설계 v0.1

> 목표: **하드웨어 없이 스마트폰 앱만으로**, 차에서 내리는 순간부터 여러 신호를 조합해 기억하고, 돌아올 때 "몇 층 / 어느 방향 / 몇 m"를 안내한다.
> 대응 시나리오 100개: [scenarios.md](./scenarios.md) (본문의 `A01`, `B05` 같은 ID가 시나리오 번호)

## 0. UX 원칙: 0탭 기록 · 0탭 안내 · 1탭 교정

| 원칙 | 의미 |
|---|---|
| 0탭 기록 | 주차할 때 사용자는 아무것도 하지 않는다. 엔진이 알아서 감지하고 저장한다. |
| 0탭 안내 | 돌아올 때 화면은 **한 장**이다: 층 배지 + 화살표 + 거리. Android는 자동으로 뜨고, iOS는 위젯 1탭. |
| 1탭 교정 | 틀렸을 때만 층 배지를 길게 눌러 고친다. 그 1탭이 엔진 학습 데이터가 된다. |
| 한 번에 하나 | 화면에는 지금 해야 할 행동 하나만 보여준다. 지도는 없다. |
| 정직한 화면 | 모르면 모른다고 표시한다. 확신이 없으면 화살표를 넓은 부채꼴로 그리고, 화살표 대신 사진을 보여준다. |
| 기본은 침묵 | 운전 중에는 UI가 없다(H05). 차를 찾는 상황이 아니면 소리·진동도 없다(E12, E13). |

## 1. 시나리오 100개에서 도출한 설계 원칙 9가지

| # | 원칙 | 왜 필요한가 | 대표 시나리오 |
|---|---|---|---|
| P1 | **짧은 변화량만 믿는다** | 절대 기압은 날씨 때문에, 나침반 절대 방위는 철골 때문에 믿을 수 없다. 몇 분 안의 변화량은 믿을 수 있다. | B01, B02, B06, C02, E01 |
| P2 | **앵커 체인** | 경로를 하나의 긴 궤적이 아니라 "앵커(기준점) 사이의 짧은 구간" 그래프로 저장한다. 오차는 앵커에서 리셋된다. | B14, C03, E04 |
| P3 | **증거 합산** | 어떤 신호 하나에만 의존하면 반드시 깨지는 시나리오가 있다. 여러 신호에 가중치를 주고 합산한다. | A01–A07, F03, F12 |
| P4 | **시간 되감기** | 진짜 하차 시점은 나중에야 알 수 있다. 10분 링버퍼로 사후에 되감아 원점을 잡는다. | A05, A06, B08 |
| P5 | **정답은 공짜로 온다** | 차 블루투스가 다시 연결되는 순간 사용자는 차 안에 있다. 매 주행이 자동으로 정답 데이터를 만든다. | E08, E09, C05 |
| P6 | **정직한 강등** | 신뢰도 등급(T1~T4)에 따라 보여줄 정보가 달라진다. 틀린 화살표보다 정확한 사진이 낫다. | B15, E03, E15 |
| P7 | **장소는 학습된다** | 층 이름, 층고, 엘리베이터 위치는 장소마다 다르다. 자주 가는 곳일수록 정확해진다. | B05, B07, F09, F10 |
| P8 | **기본은 침묵** | 차를 찾을 때만 말한다. | E12, E13, H05 |
| P9 | **온디바이스 우선** | 위치 데이터는 폰 밖으로 나가지 않는다. 법적 리스크와 거부감을 동시에 줄인다. | H01, H02 |

## 3. 상태 머신

```
                ┌──────────────────────────────────────────────────────┐
                ▼                                                      │
IDLE ──(차 연결 / 차량 활동)──▶ DRIVING ──(BT 해제 or 정차+걸음)──▶ WALK_OUT
                                  ▲                                 │   │
                                  │      (차 재연결 + 이동: A10)    │   │
                                  └─────────────────────────────────┘   │
                                                                        │ 종료 조건
                                                                        ▼
           ┌──────────(차에서 멀어짐 / 위층 복귀: E12, E13)──────── PARKED
           │                                                       │   ▲
           ▼                                                       │   │ 다른 교통수단 (F03)
         ARMED ◀────────────(무장 트리거: §5.7)────────────────────┘   │ = 기록 유지
           │                                                           │
           │ (차 층 도달 or 앱 열기)                                    │
           ▼                                                           │
        GUIDING ──(차 BT 재연결 or 차 기록 근처에서 차량 출발)──▶ FOUND ─┴─▶ DRIVING
                                                              │
                                                              └─▶ [LL] 정답 학습
```

| 상태 | 센서 사용 | 종료 조건 |
|---|---|---|
| IDLE | 없음(OS 트리거만) | 차 연결 / 차량 활동 감지 |
| DRIVING | 저율: 기압 1Hz, GNSS 품질, 자이로 회전율, 활동 → 링버퍼 | 주차 점수 ≥ θ_park (§5.2) |
| WALK_OUT | 고율: 기압 10Hz, IMU·지자기 50Hz, 걸음, Wi-Fi(Android) | ① 집/회사 앵커 도착 ② GNSS 실외 60초 안정 ③ 15분 경과 ④ 10분 정지 중 하나 |
| PARKED | 없음 | 무장 트리거 |
| ARMED | 저율 기압(높이 추적) | 차 층 도달 → GUIDING / 멀어짐 → PARKED |
| GUIDING | 고율(WALK_OUT과 동일) | FOUND / 10분 진척 없음 → PARKED |
| FOUND | — | 즉시 학습 후 DRIVING |

```text
ParkingRecord {

  t_park                           // 단조 시계 + 표시용 시각 (G06)

  site_id                          // SiteProfile 참조
  graph: AnchorGraph               // 핵심. 아래 참조
  floor: {

    dh_home_m:   float?            // 집/회사 앵커 기준 원시 높이차 (B06)
```

## 5. 모듈별 알고리즘

### 5.1 [SB] 센서 링버퍼 · 능력표

- **링버퍼**: DRIVING 중 최근 10분을 유지한다(기압 1Hz, GNSS 품질 1Hz, 자이로 회전율 10Hz, 활동). 30초마다 디스크에 저장해서 재부팅·업데이트 후에도 복구한다(G05).
- **능력표**: 앱을 처음 실행할 때 측정해 둔다.

```text
Capabilities {
  has_baro, baro_noise_pa          // 정지 상태 30초 분산으로 측정 (B16)
  has_gyro, has_mag, has_step
  can_wifi_scan                    // iOS: false
  bg_level: FULL | LIMITED | NONE  // 권한·절전 상태 (G01–G03)
}
```

- **강등 우선순위**(배터리 부족 시, D07): 기압 > 걸음 > 자이로 > 지자기 지문 > Wi-Fi 지문 순으로 남긴다.
- **GNSS 품질 게이트**(C11, C13): 정확도 ≤ 15m, 위성 수 ≥ 6, 기압상 지하가 아닐 것. 이 세 가지를 모두 통과한 위치만 사용한다.

### 5.2 [PD] 주차 감지 — 증거 합산

| 증거 | 가중치(초기값) | 시나리오 |
|---|---|---|
| 차 BT / CarPlay / Android Auto 해제 | +0.6 | A01, A02 |
| 활동: 차량 → 도보 전환 | +0.4 | A03 |
| 차량 이동 후 GNSS 속도 ≈ 0이 30초 이상 | +0.2 | A03 |
| 지하 진입 패턴(주행 중 GNSS 끊김 + 차량 램프 하강) | +0.2 | B08 |
| 수동 '주차' 위젯 | +1.0 | G03 |
| **부정**: 차량 진동·속도가 계속됨 | −1.0 | A07 |
| **보류**: 해제 후 걸음 없음 | 판정 보류 | A08 |

```text
on_event(e):
  score = Σ w_i · evidence_i(window = 최근 2분)
  if score ≥ θ_park (0.6):
     t0 = rewind(ring_buffer, "마지막 차량 움직임 이후 첫 걸음")      // A05, A06
     kind = classify_kind()                                          // 아래
     start WALK_OUT(origin = CAR anchor @ t0)

classify_kind():
  if 하차 위치 GNSS 양호 and 지하 진입 이력 없음 and site.flags.valet  → VALET
  if site.flags.mechanical                                            → MECHANICAL
  if 차 BT 미연결 and 차량 활동만 있었음                              → PASSENGER 또는 임시 차량
  else                                                                → NORMAL
```

- **다른 교통수단 구분**(F03): PARKED 상태에서 차량 활동이 감지되더라도, 차 BT가 없고 차 기록에서 30m 이상 떨어져 있으면 FOUND가 아니다. 기록을 유지한다.
- **지하차도 오인 방지**(F12): GNSS가 끊긴 상태에서 정차·하차가 일어나야 지하 주차로 판단한다. 주행 중에 GNSS가 다시 잡히면 무효로 한다.

### 5.3 [VS] 수직 분할 · 층 추정

**① 기압 → 높이 전처리**

```text
p  = median_filter(p_raw, 1s) → lowpass(0.5Hz)
p  = remove_spikes(p, 원복 시간 < 5s)                 // B03 방화문·환기팬
s  = 정지/수평 구간의 기압 기울기(Pa/s, 최근 3분)       // B02 날씨 추세
p' = p − s·t
h  = −(p' − p_ref) / (ρ·g)     // 해수면 근처 ρg ≈ 12 Pa/m → 1Pa ≈ 0.083m
```

**② 평탄부 · 수직 구간 분할**

- 평탄부: 수직 속도 |dh/dt| < 0.05 m/s가 3초 이상 이어지는 구간
- 수직 구간의 높이 변화 = (다음 평탄부 중앙값) − (이전 평탄부 중앙값)
- 이 값은 **엘리베이터 안이 아니라 내려서 걷기 시작한 뒤 평탄부**에서 측정한다(B04).

**③ 이동 수단 분류** (초기 규칙 → 실측 데이터로 분류기 학습)

| 분류 | 수직 속도 | 걸음 | 기타 특징 | 시나리오 |
|---|---|---|---|---|
| ELEVATOR | > 0.8 m/s | 거의 없음 | 출발·정지 가속 펄스 | B12, B18 |
| ESCALATOR | 0.2–0.8 m/s, 일정 | 거의 없음 | 10초 이상 지속 | B11 |
| STAIRS | 0.1–0.5 m/s | 있음 | 층참 정지 패턴 | B10, C14 |
| RAMP_WALK | < 0.15 m/s | 있음 | — | B20 |
| RAMP_DRIVE | > 0.1 m/s | — | 차량 활동 + 자이로 누적 회전(나선) | B08 |

**④ 층 추정 — 두 개의 독립 추정을 교차 검증**

```text
F_drive = 지하 진입 순간(주행 중 GNSS 끊김)의 기압 → 차 옆 첫 도보 평탄부
          (링버퍼에서 계산. 차 안 압력차를 피하려고 도착점은 차 밖에서 잰다: B17)
F_walk  = 차 옆 평탄부 → GROUND_EXIT(GNSS 재수신) 또는 HOME 앵커
          (몇 분 안의 변화라 날씨 무관: B01)

if 둘 다 있음:
   if |F_drive − F_walk| < 0.4 · floor_height:  dh = 품질 가중 평균; conf = 높음
   else:                                        dh = F_walk;         conf = 중간
elif 하나만 있음:                                dh = 그 값;          conf = 중간

label = site.levels.nearest(dh_ground)        // 학습된 레벨에 매칭 (B05, B07, B09)
     ?? sign_label(round(dh_ground / H_default))   // 학습 없음: 기본 층고 3.0m (F09)
```

- **집↔차 연결**(B06, E01): 집 앵커와 차 사이는 '층수'가 아니라 **원시 높이차(m)**로 저장한다. 주차장 층고와 주거층 층고가 달라도 상관없다.
- **층 변경 히스테리시스**(B20): 0.6개 층 이상 바뀌어야 층이 바뀐 것으로 인정한다.
- **기압계가 없을 때**(B15):
  - 나선 램프의 자이로 누적 회전(360° ≈ 1개 층, 사이트별 비율 학습)
  - 엘리베이터 탑승 시간
  - 사진 글자 인식
  - "B3 맞나요?" 1탭 확인
  - 위 수단을 쓰되 신뢰도 상한은 '중간'으로 둔다.

### 5.4 [PDR] 수평 추적

```text
for each step k:
   mode   = classify_carry(orientation, accel)        // 손/흔듦/주머니/가방/통화 (D01–D04)
   L_k    = user.step_a · f_step + user.step_b        // 보폭, 사용자별 학습 (C05)
   Δψ     = gyro_yaw_about_gravity(dt) − heading_bias // 나침반 사용 안 함 (C02)
   if mode changed:  Δψ = 0                           // 꺼내는 순간 회전 오인 방지 (D05)
   φ      = PCA(수평 가속도, 최근 4걸음)              // 폰-진행방향 오프셋 (D02)
   ψ_k    = ψ_{k-1} + Δψ
   ψ_snap = snap(ψ_k, site.grid_angle + n·90°, tol = 15°)   // 격자 스냅 (C01, C04)
   pos   += L_k · [cos ψ_snap, sin ψ_snap]
   σ²    += (σ_L)² + (L_k · σ_ψ)²                     // 불확실성 누적 → 앵커에서 리셋 (C03)
```

| 특수 처리 | 규칙 | 시나리오 |
|---|---|---|
| 차 주변 루프 접기 | 출발 직후 원점 반경 3m 안의 움직임은 '차 주변 활동'으로 접고, 마지막 이탈 시점부터 경로 시작 | C08 |
| 계단 수평 0 | STAIRS 구간은 수평 이동을 0으로 처리 | C14 |
| 무빙워크·카트 | 걸음과 이동이 불일치하면 해당 구간 길이를 '미상'으로 두고 σ 확대 | C06, C15 |
| 격자 방향 추정 | 사이트 학습값이 있으면 사용. 없으면 첫 번째 긴 직선 구간의 방향 | C01 |

### 5.8 [LOC] 위치 추정 — 3단계

```text
① 수직:  Δf = level(현재 높이) − level(차)
         현재 높이는 짧은 구간 체인으로 계산: HOME → (엘리베이터 Δh) → 현재    // P1
② 위상:  지금 어느 앵커에 있나?
         S(a) = w_mag·sim_mag(a) + w_wifi·sim_wifi(a) + w_h·[Δh 일치]
              + w_seq·[방금 엘리베이터에서 내림 → 차 층 ELEVATOR_DOOR가 유력]
              + w_gnss·[GNSS 일치]
         최고 점수 앵커 a* (점수 < θ_anchor이면 '미확인')
③ 거리:  a* 기준 좌표계에서 파티클 필터 (N = 200)
         예측: PDR 걸음 + 잡음
         보정: 자기장 수열 DTW 매칭(기록된 경로의 역순 대비) → 경로상 위치 우도
               Wi-Fi 유사도(Android)    → 차까지 거리 우도
               사이트 보행 가능 영역(학습됨) → 제약
         출력: û(내 위치), ĉ(차 위치), d̂ = |ĉ − û|, β = 차 방향, σ(불확실성)
```

- **경로 이탈**(E06): 경로 가설의 우도가 급락하면 역경로 매칭을 끄고 벡터만 사용한다.
- **잘못된 층**(E05): 엘리베이터 문이 열린 뒤 평탄부에서 Δf ≠ 0이면 즉시 GD에 '층 경고'를 보낸다.

### 5.9 [GD] 안내 모드 · 피드백

**모드 선택** (위에서부터 먼저 맞는 것 하나만 표시)

```text
if Δf ≠ 0:                                  FLOOR   "▼ 2개 층 더 내려가세요"   (E05, E11)
elif 현재 구간이 복도/홀 and 기록된 회전 있음: STEP    "나가서 오른쪽, 15m"       (C10)
elif tier == T1:                            VECTOR  화살표 부채꼴 + "18 m"     (C09)
elif tier in (T2, T3):                      MEMORY  층 + 기둥 사진 + 평소 엘리베이터 (E03)
else:                                       NONE    "기록 없음" + 마지막 GNSS·진입 지점 (E15)

if d̂ < max(4m, 1.5σ):                      ARRIVE  "이 근처예요" + 사진 + 비상등 안내 (E07, A11)
```

**화살표**

- 방향: β − ψ_now. 위치 갱신이 느려도 자이로로 30Hz 회전한다.
- 부채꼴 폭: clamp(atan(σ / d̂) + σ_ψ, 10°, 90°). σ는 위치 오차, σ_ψ는 방향 오차(첫 방문 약 ±20°, 학습 후 약 ±4°, 초기값). **좁을수록 확실하다는 뜻**이다(정직한 화면).
- |β − ψ_now| > 120°이면 화살표 대신 "뒤로 돌아보세요"를 표시한다.

**비프 · 진동 · 점멸**

```text
if σ < 0.5 · d̂:   T = clamp(0.1 + 0.06 · d̂, 0.15s, 2.0s)    // 30m→1.9s, 10m→0.7s, 3m→0.28s, 1m→0.16s
else:             T = 1.5s 균일 '탐색 펄스'                  // 거리를 아는 척하지 않음
```

| 채널 | 기본값 | 비고 |
|---|---|---|
| 진동 | 켜짐 (GUIDING 중) | 화면을 안 봐도 되도록 (H04) |
| 소리 | 앱이 화면에 떠 있고 '찾기' 중일 때만 | E12 오작동 방지 |
| 화면 점멸 | ARRIVE에서 켜짐 | 비프와 동기화 |
| 차량 비상등 | 제조사 API 연동 시 ARRIVE에서 1회 | 테슬라 Fleet API `flash_lights` 등 |

### 5.10 [CF] 신뢰도 · 표시 등급

```text
c_floor ∈ [0,1] = f( F_drive/F_walk 일치도, 기압계 품질, 사이트 학습 성숙도,
                     사진 라벨 일치, 사용자 확인 )
σ_h (m)         = LOC 출력

T1 정밀:  c_floor ≥ 0.9 and σ_h ≤ 5m and 앵커 확인됨   → 화살표 + 거리 + 비프
T2 안내:  c_floor ≥ 0.7 and 경로 그래프 있음           → 단계 안내 + 사진
T3 기억:  층 라벨 또는 사진 있음                        → 층 + 사진 + 평소 엘리베이터
T4 모름:  그 외                                         → 마지막 GNSS + 시각 + 평소 주차 구역
```

**규칙: 등급이 화면을 결정한다.** 서로 모순되는 정보(예: 화살표는 오른쪽, 텍스트는 왼쪽)는 절대 같이 보여주지 않는다.

### 5.11 [LL] 학습 루프 — 정답은 공짜로 온다

```text
on FOUND (차 BT 재연결, 또는 차 기록 반경 안에서 차량 출발):
   truth = 이 순간 사용자 위치 = 차 위치
   e     = ĉ − truth                                 // 엔진의 차 위치 추정 오차
   if |e| > 30m: discard                             // 이상치 제거
   user.step_scale   ← (1−η)·step_scale + η·(실제 경로 길이 / 추정 경로 길이)   // η = 0.1
   user.heading_bias ← 회전 오차의 지수평균
   site.anchors      ← 이번 그래프를 사이트 지도에 정렬·병합
   site.levels       ← dh 관측 추가 (레벨 군집 갱신)
   site.parking_prior← 차 위치 히트맵 갱신
   ParkingRecord 원시 로그 삭제                       // H01

on USER_CORRECTION (층 배지 교정, D10):
   해당 레벨 라벨 갱신 → 같은 사이트 기록 전체 재계산
```

여기서 생기는 **데이터 해자**: 같은 장소를 자주 쓸수록 레벨·라벨·앵커 지도가 정교해지고, 신뢰도 등급이 T3 → T1로 올라간다.

## 6. UX 명세

### 6.1 화면은 세 개뿐

**① 저장 알림** — 새 장소이거나 신뢰도가 T1 미만일 때만 표시. 그 외에는 위젯만 조용히 갱신.

```
🅿 B3에 주차했어요 · 엘리베이터에서 32m      [📷 기둥 찍기]
```

**② 안내 화면** — 단일 화면

```
┌───────────────────────────┐
│            B3             │  ← 층 배지. 현재 층이 다르면 "▼ 2"로 바뀜
│                           │
│            ▲              │  ← 화살표. 부채꼴 폭 = 불확실성
│          ╱   ╲            │
│          18 m             │
│                           │
│     [ 기둥 사진  C-17 ]    │  ← 있을 때만
└───────────────────────────┘
   층 배지 길게 누르기 = 층 교정 (1탭 교정)
```

**③ 위젯 / 잠금화면**

```
🅿 B3 · C-17 · 어제 19:30
```

### 6.2 온보딩: 권한 3개로 끝

1. 위치(항상) · 동작 및 피트니스 · 근처 기기(블루투스) 권한
2. **차 선택 화면은 없다.** 차량 활동 중 2회 이상 연결된 BT 기기를 차로 자동 인식한다.
3. **집 층수 입력도 없다.** 밤새 머무는 장소를 집 앵커로 자동 학습한다.

### 6.3 문구 규칙

- 한 번에 행동 하나만 보여준다.
- 숫자는 반올림한다(17.6m → 18m).
- 확신이 없을 때 "~" 기호를 쓴다("약 B2").

## 9. 검증 계획

### 9.1 개발 방식: 로그 재생

1. **센서 로깅 앱**을 먼저 만든다. 모든 센서 원시값과 이벤트를 기록한다.
2. 정답은 **차 BT 재연결 시점**에서 자동으로 얻는다(P5). 별도 측량이 필요 없다.
3. 엔진은 로그 재생기 위에서 오프라인으로 돌린다. 파라미터를 바꿀 때마다 전체 로그로 회귀 테스트한다.

### 9.2 현장 테스트 행렬

| 축 | 값 |
|---|---|
| 장소 | 아파트 3곳(평지·경사지·스플릿 레벨), 대형마트 1곳, 오피스 1곳 |
| 휴대 방식 | 손 · 주머니 · 가방 · 통화 |
| OS | iOS 1종, Android 2종(기압계 있는 기종 / 없는 기종) |
| 반복 | 조합당 10회 이상 |

### 9.3 성공 기준 (제안 목표치)

| 지표 | 목표 |
|---|---|
| 주차 자동 감지 재현율 / 정밀도 | ≥ 95% / ≥ 98% |
| 층 판별 정확도 (기압계 있는 기종) | ≥ 95% |
| 최종 위치 오차 CEP50 / CEP90 | ≤ 4 m / ≤ 8 m |
| T1 등급 도달 비율 (자주 가는 장소) | ≥ 80% |
| 배터리 소모 | ≤ 하루 2% |

**최종 위치 오차가 CEP90 8m를 넘으면** 앱 단독 전략을 재검토하고, 차량 태그 병행으로 전환한다.
